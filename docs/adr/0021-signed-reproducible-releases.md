# ADR-0021: Releases are reproducible, carry an SBOM, and are signed with cosign

* Status: accepted
* Date: 2026-11-06

## Context
Stage 7 asks for Cosign-signed Lambda packages and an SBOM. The Lambda package is small (first-party code plus the policy file),
its only third-party dependency (boto3) is provided by the Lambda runtime, and the project must run without network access in
tests.

## Decision
1. **The zip is reproducible.** `response/package_lambda.sh` produces the same bytes from the same source (three builds gave the same
   hash). Its checksum file now uses a relative name, so `sha256sum -c` works on a copy.
2. **The SBOM is generated by a small script** (`release/sbom.py`, CycloneDX 1.5): the artifact, every file with its hash, and the
   runtime dependencies, marked `excluded` because the runtime provides them. Its composition says
   `incomplete_first_party_only`, which is true. It is validated against the official schema by `make sbom-validate`.
3. **Two signing modes in one script** (`release/release.sh`). In CI: keyless, with the workflow's GitHub OIDC identity and no key
   to guard. Locally and in tests: a throwaway key and a signing config with no transparency log, so nothing is uploaded and
   verification says that the log was not checked.
4. **Three signed things:** the zip, the SBOM, and an attestation that binds the SBOM to the zip's digest. Verification checks the
   checksum, all three signatures, and the binding; any failure exits non-zero.
5. **Third-party tools are pinned.** cosign is downloaded at a fixed version and checked against a fixed sha256; gitleaks at a fixed
   version. Third-party actions are pinned by major tag like the rest of the repo, not by commit.
6. **Secrets scanning** runs gitleaks over the history, with an allowlist of the repository's own fake keys by exact value.

## Consequences
* (+) The tests use the real cosign: a changed zip, a changed SBOM, another key, and an SBOM attested to a different zip all fail.
* (+) Tampering found a real bug on the first try (the absolute path in the checksum file).
* (+) Local-key mode detects cosign v2 or v3 (they need different flags to upload nothing); the tests pass on v2.5.3 and v3.1.4.
* (-) The keyless path has not run yet. It runs on the first `v*` tag, and until then that path is untested.
* (-) Nothing checks the signature when the package is deployed. Signing without verifying at the point of use protects less than it looks.
* (-) boto3 is unpinned because the runtime provides it, so the SBOM cannot say which version runs.
* (-) Pinning actions by commit is a follow-up.
